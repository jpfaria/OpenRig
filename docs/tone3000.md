# TONE3000 browser (#879)

OpenRig no longer ships NAM captures or IRs that come from
[TONE3000](https://www.tone3000.com) in its installer. Packs from every other
source (native, LV2, VST3, the remaining NAM/IR packs) are still bundled.
Users search TONE3000 from inside the app and install what they want. Each
user does this with their own key.

## The user's key

TONE3000's API v1 needs a **Secret Key** (`t3k_cs_…`). Each user creates their
own at <https://www.tone3000.com/settings>. They sign in, then open the API keys.
The key goes in **Settings → System → Integrations → TONE3000 Secret Key**.
That card has a link that opens the TONE3000 page.

- The key is per machine, so it lives in `config.yaml` as `tone3000.api_key`
  (see [config-taxonomy.md](config-taxonomy.md)). It never travels with
  `project.yaml`.
- The UI only shows whether a key is set (a status pill). It never shows the
  key. `Debug` output redacts it.
- Saving applies at once, with no restart. A blank value clears the key.

## The window

Open it from the **T3K** logo button in the chains top bar. The button sits
between the mixer and the settings gear.

- **Browse** tab:
  - A search field.
  - Three filter rows: **Format** (All / NAM / IR), **Gear** (All / Amp /
    Full rig / Amp + Cab / Pedal / Outboard / Cab) and **Sort** (Best match /
    Trending / Most downloaded / Newest).
  - Paged results. Each result card shows the title, author, downloads and
    tags with how many A1, A2 and IR captures the tone holds.
  - Each NAM result has an **A1 / A2** choice. It defaults to A2 when the tone
    has A2 captures. An architecture the tone has no captures for is dimmed.
  - Each result has an **Install** action. It shows progress
    (fetching → downloading N/M → measuring), then **INSTALLED**. A failed
    install shows **RETRY** and the reason, in red.
- **Without a key**, the Browse tab says a key is needed and offers
  **Open settings**. That opens the settings on the Integrations section.
- **Installed** tab: every installed TONE3000 package, with its block type,
  architecture and capture count. Uninstall takes two clicks: the trash icon,
  then the red confirm.

## What Install does

Install downloads **every** capture of the tone for the chosen architecture.
It then builds a normal plugin package, with the same manifest format as the
bundled packs. The steps reuse the existing tools:

- **Parameters.** They come from the capture names through the axes
  dictionary and the parameter gate. The result is real knobs and choices,
  not a flat `model` list.
- **Level.** Each capture gets an `output_gain_db`, measured the way
  `loudness_audit` measures it. A NAM capture is run on a synthetic guitar DI.
  An IR is set by peak level.
- **Block type.** It follows the tone's gear.

The download goes into a hidden staging folder. The manifest is written last,
so a catalog scan never sees half a package. Any failure removes what was
written.

Packages install under a `tone3000/` folder next to `config.yaml`, apart
from the bundled and user plugin trees. Changing `paths.plugins_path` never
hides them. Plugin ids are `tone3000_<tone>_a1` / `tone3000_<tone>_a2` for
NAM and `tone3000_<tone>` for IR. The catalog reloads after an install or an
uninstall, so the new model shows up in block pickers at once.

## Commands and reads

Every action is a `Command::Tone3000(…)`, so MCP and any other controller do
exactly what the window does:

- `SearchTone3000`
- `InstallTone3000`
- `UninstallTone3000`
- `SetTone3000ApiKey`

The browser state is served at `openrig://tone3000`
(see [mcp.md](mcp.md)). It never contains the key.
